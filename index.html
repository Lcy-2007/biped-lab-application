我是郑州大学电气与信息工程学院自动化类的二年级本科生。我的动手经历是从一块 51 单片机开发板开始的—— 从只会照着例程点灯，到能自己翻数据手册、配寄存器、调时序，把一个个"不动"的模块调成"能动"的模块。

之后我用 STM32 做了一次系统性的外设训练：定时器、PWM、ADC、串口、中断与状态机的配合， 也开始真正理解"实时"这两个字——数据什么时候采、什么时候算、按键什么时候发出去，都是有约束的。

带着这些底子，我独立开发了 「面向虚拟控制的多模态肢体映射与交互中枢」： 底层用 Python 做视觉感知、识别使用者的肢体动作，中间层用 Unity GUI 做状态中枢与映射管理， 顶层把它翻译成键盘按键执行——于是任何支持键盘的软件都能被它控制。 它是我第一次把"感知 → 中枢 → 执行"这条三层链路自己跑通。

也正是这个项目，让我意识到自己真正的兴趣所在：让机器"看懂"并"理解"物理世界。 我做过的是"把人的动作翻译成键盘按键"，而 3D 识别做的是"把真实场景变成机器能计算的三维信息"—— 两者都在解决同一个问题：如何把物理世界可靠地映射进数字世界。这也是我选择 3D 方向最直接的原因。

01 我想解决什么问题

传统的虚拟控制基本依赖键鼠或手柄——维度少、不直观。但有一件事我一直觉得很有意思：键盘是电脑最通用的输入接口， 几乎所有的软件都认它。所以我想做的不是给每个软件单独写一套专用接口，而是让肢体动作直接变成键盘按键—— 只要这一步走通，就等于同时打开了所有支持键盘的软件。而且这套映射是可配置、可复用的，不针对某一个场景硬编码。

02 我是怎么做的

  • 底层 · 视觉感知（Python）：用摄像头采集画面，在 Python 侧完成图像预处理与肢体关键点检测， 把"画面里的动作"变成结构化状态（动作类别 + 置信度 + 关键坐标），再稳定地推给上层。
  • 中间层 · 状态中枢（Unity GUI）：用 Unity 搭建中间的状态中枢与人机界面——接住底层推来的状态， 负责状态管理、动作去抖、映射规则配置，同时把当前状态、识别结果与调试信息实时可视化，边调边看。
  • 顶层 · 终端执行：把中枢确认后的状态翻译成键位指令并执行，最终表现为标准键盘输入—— 不需要给每个软件单独写接口，任何支持键盘的软件都能被直接控制。
  • 跨层协同：三层之间约定轻量消息格式（状态名 + 置信度 + 时间戳）， 保证上层拿到的永远是一帧完整状态，不会出现"读到一半"的脏数据。
  • 稳定与鲁棒：加入滑动平均、置信度阈值与状态最短保持时间抑制抖动； UI 侧还支持手动暂停与覆写，方便逐帧排查边界情况。

03 我从中真正学到的东西

  • 把一个大问题切成"感知 → 中枢 → 执行"三层之后，每层职责单一、都能单独调——定位问题的速度完全不一样。
  • 中间层不是多余的：识别结果直接用会抖得厉害，多加一层状态中枢做去抖和规则管理，整个系统的可用性提升了一个档次。
  • 实时性是可以被"算"出来的：采集帧率、识别耗时、状态推送频率，三者必须先对齐，再写代码。
  • 也踩过坑：早期没有置信度阈值和最短保持时间，同一个动作会在好几个键之间反复跳变， 最后是靠阈值 + 状态保持 + 在 Unity 界面里逐帧对照才压下去。

我对这个方向的理解：三条主线

01

视觉感知与图像处理

相机负责"看见"：图像与深度信息的采集、预处理、感兴趣区域提取与目标定位。这一层决定了后面所有计算的输入质量。

  • 彩色 + 深度信息对齐
  • 去噪 / 畸变校正 / ROI 提取
  • 光照与复杂背景的干扰
我的连接点：外设驱动与传感器数据采集是我的强项，这一层的"取数"逻辑和我做过的多通道采集是相通的。
02

目标检测与三维识别

用 YOLO 这类深度学习算法识别目标物品（类别、数量），再结合深度信息判断它在空间中的位置，并对结果做优化。

  • 目标检测模型的训练与推理
  • 深度 → 三维坐标换算
  • 类别 / 数量 / 位置的联合输出
我的连接点：这是我目前差距最大、也最想补的一块——已经开始从 Python、OpenCV 到 YOLO 训练流程系统地学。
03

机器人系统集成与工程实践

相机、云台、裁判盒和计算平台要协同工作：模型部署、实时推理、结果输出与现场调试——最终比拼的是整个系统能不能稳定跑。

  • 多设备协同与通信
  • 模型部署与实时性约束
  • 现场调试与异常处理
我的连接点：这一层最像我做过的项目——多模块协同、跨层数据约定、实时性与现场调试，都是我已经踩过一遍的坑。
